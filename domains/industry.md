## 一、分层架构（抽象层通用 + 行业层可插拔）

```
QCM = 抽象层（不变） + 行业适配层（可插拔）
      │                  │
      │                  ├─ 适配包 A：制造业（reference，现有 10 场景即深度参考实现）
      │                  ├─ 适配包 B：IT / 软件
      │                  ├─ 适配包 C：服务业
      │                  ├─ 适配包 D：医疗健康
      │                  └─ 适配包 E：物流供应链 …
      │
      └─ 抽象层（只读资产，跨行业通用）：
           组织四层（战略/管理/业务/执行）│ 流程四面（系统/管理/过程/产品）
           16 格主矩阵 │ 多链（发生/流出/系统）│ 六步导航 │ 决策 L1-L4
           MDS v3.3 输入契约 │ 五价值链（产品规划/开发/采购/制造/售后）
```

**核心解耦点**：行业差异集中在 4 个绑定点——① 端到端流程（MTL/LTC/OTC/ITR 的行业化映射）② F10b 工序细分 ③ 典型质量场景 ④ 工具落格差异。适配包只需定义这 4 点，其余全部继承抽象层。

## 二、行业适配包模板（ADAPTER 七段）

### 2.0 制造业包与行业适配包的关系（先读此节）

> **一句话**：制造业包 = 抽象层的"孵化原型"（reference / 母版），行业适配包 = 抽象层的"增量映射"（特别法）。两者不是平级兄弟，而是"基准参照物"与"对照基准的差异层"。

| 维度 | 制造业包（MFG） | 行业适配包（如 IT） | 关系 |
|---|---|---|---|
| 定位 | reference 参考实现（母版） | 增量映射层（特别法） | 基准 vs 派生 |
| 内容 | 七段**全量**（10 场景/86 工具/8 案例全深度） | 只写**差异点**（端到端流程/F10b/场景/工具落格差异） | 全量 vs 差异 |
| 落盘 | **逻辑映射**（内容留在原 33 文件，不复制） | **物理适配包**（独立文件 `adapters/xx-adapter.md`） | 源不动 vs 新落盘 |
| 通用工具 | 拥有权（86 工具在 tools.md，属抽象层资产） | 复用权（用 `##A01` 等编号引用，不复制） | 拥有 vs 引用 |
| 蒸馏对标 | —（自身即模板） | 以 MFG 为对标基准，逐段问"这行业对应物是什么" | 模板 vs 对照 |
| 判据参考 | 拥有基准判据（Cpk≥1.33 等） | 以 MFG 判据为起点，调研校准行业阈值 | 基准 vs 校准 |

**关键不对称性**：
- 制造业内容**就是**抽象层的实体化——tools.md 的 86 工具（SPC/8D/FMEA 等）本就跨行业通用，属抽象层资产，**不该被封装进适配包文件**（否则等于把通用资产私有化）
- 新行业与制造业的**差异**才是适配包的价值（IT 的代码走查/部署门控、医疗的 GMP/患者安全链）——适配包只装差异，通用部分引用即可
- 因此：制造业包 = **逻辑映射登记**（七段→文件路径），新行业 = **物理适配包**（只装差异）——这个不对称本身就是两者关系的体现

**蒸馏时的协作关系**：

| 场景 | 制造业包的角色 |
|---|---|
| 新行业蒸馏启动 | 对标模板：新行业对照七段逐段问"这行业对应物是什么？" |
| 工具落格差异分析 | 复用清单：先勾"能直接复用哪些 86 工具"，再补行业特有方法 |
| 判据/阈值参考 | 起点参考：MFG 判据作起点，新行业调研校准（如 IT 缺陷密度 SLA） |
| 测试验证 | 回归基线：新行业增量用例叠加在 8 引擎基线上，不得破坏 |

### 2.1 适配包模板（ADAPTER 七段）

  | 抽象流程 | 行业化流程 | 价值链映射 | 流程性质 MP/COP/SP |
- 关键法规/标准：{行业标准清单，如 IT→ISO 27001/ISO 20000；医疗→ISO 13485/GMP}

## D. 工序细分（F10b 行业版）

- 映射原则：能用通用工具（SPC/8D/FMEA/5S 等）不新建，行业特有方法才挂"行业工具扩展区"

## A. 典型质量场景（3-5 个，QCM 穿透标准格式）
### 场景：{格名} · {行业场景名}
MDS: {F12} | {F18} | {成熟度} | {Tier} | {紧迫度}
穿透: {L2选型} → {L3执行} → {L4治理}

## E. 案例锚点（Evidence Anchors）

- 黑名单：知乎/公众号/百度百科不采信为权威源

## R. 注册与版本（Registration）

- 注册动作：ima_skill_create 重注册 + extension-guide 扩展记录表追加

## 三、行业蒸馏 SOP（QCM 进化分支：Infoseek 全景调研 + QCM 穿透补充）

### 3.1 触发条件（任一命中即启动）

```
① 六步导航端到端定位：MTL/LTC/OTC/ITR 在目标行业无对应流程
② F10b 工序细分：无目标行业工序（如"需求评审/代码走查/部署发布"）
③ 场景库：无目标行业典型质量场景匹配
④ 知识库/案例：目标行业案例缺失，且用户要求行业化应用
```

### 3.2 蒸馏流程（六步，每步有交付物）

```
阶段一 Infoseek 全景调研（信息收集）
  ① 关键词三层展开（行业×质量维度×场景）→ 多渠道嗅探
  ② Anchor_Score 锚点评分门控（≥70 核心 / 40-69 需确认 / <40 过滤）
  ③ 内容采集（URL 存活预检 → 四级降级 → 翻译摘要）
  ④ 多源交叉核验（标准+经典+交叉，产出分层根因表）
  交付物：行业调研包（价值链/标准/工具/案例/判据 五件套）

阶段二 QCM 穿透补充（结构化落位）
  ⑤ 六步导航逐层穿透：端到端→外轴→内轴→多链→横轴 16 格→纵轴→取物
  ⑥ 工具落格差异分析（复用 vs 新增）
  交付物：适配包草稿（ADAPTER 七段模板）

阶段三 测试与注册（质量门控）
  ⑦ 增量测试用例补入 test-cases.md（场景→格/工具→场景双向）
  ⑧ 8 引擎全量回归（all/cross/super/reverse/loop/combo/lowfreq/full）
  ⑨ 全绿 → ima_skill_create 注册；失败 → 回阶段二修正
  交付物：🟢 已注册适配包 + 回归报告
```

### 3.3 质量门控（注册前必须全过）

| 门控项 | 判据 |
|--------|------|
| 三源印证 | 每个关键判据至少 1 个权威来源（标准/经典/公开案例） |
| 双向可达 | 场景→16 格、工具→场景 无悬空 |
| 编号兼容 | 新增工具/工序编号向后兼容（工具 #43 起、工序追加） |
| 测试全绿 | 8 引擎 0 失败（含新增增量用例） |
| 抽象层只读 | 未改动组织四层/四面/16 格/多链/六步导航定义 |

## 五、与现有扩展接口的关系（不重复建设）

| 现有接口（extension-guide） | 本框架的关系 |
|---------------------------|-------------|
| A 场景蒸馏 / B 工具扩展 / C 大师蒸馏 / D 字段扩展 / E 流程扩展 / F 知识库扩展 | 适配包内部细节落库时调用（复用模板） |

## 六、兼容性保证（保护现有资产）

1. **抽象层只读**：组织四层/流程四面/16 格/多链/六步导航/MDS 定义一律不改（D1 六维组合 3696 条依赖这些定义）
2. **编号向后兼容**：新增工具从 #43 起、大师从 #22 起、字段从 F22 起、工序追加不重编
3. **新行业文件隔离（硬性）**：适配包一律落 `references/adapters/{代码}-adapter.md` 子目录，**禁止**将新行业内容写入原 33 文件（tools/scenarios/knowledge-base/governance 等仅制造业 reference 资产）；行业特有工具/工序/案例如需进入全局索引，必须经 A/B/E/F 接口登记并明确标注行业前缀。**原因**：测试脚本 `os.listdir(references)` 不递归，`adapters/` 子目录不进 8 引擎扫描范围——隔离既防内容污染，也明确"适配包未注册前不受测试保护"
4. **通用资产直接复用（硬性）**：新行业适配包引用通用工具/方法/判据时，一律写 `##A01` 等**编号引用**或指向原文件，**禁止复制内容**进适配包（防双源漂移）；仅当行业用法与制造业有实质差异时，才在 P 段写"差异描述"（引用编号 + 差异点）
5. **测试同步**：每个适配包注册前必须跑全量 8 引擎，新增增量用例只增不改；适配包注册后如需被测试覆盖，须在测试脚本中显式挂接（同 people/ 子目录机制）
