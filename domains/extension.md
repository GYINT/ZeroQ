## 二、A 场景蒸馏接口（新增案例）

### 文件位置
`scenarios.md` → 追加到"场景库"段落

### 场景模板（QCM 穿透标准格式）

```markdown
### 场景：{格名} · {案例名}
MDS: {F12问题类型} | {F18流程性质} | {成熟度级} | {Tier} | {紧迫度}
穿透: {L2选型} → {L3执行} → {L4治理}
取物: [治理-{层级}×{价值链}→{工具}] + [工具-{档位}×{场景}→{工具}] + 置信度{0.xx}
```

### 字段校验

| 检查项 | 规则 |
|--------|------|
| 格名 | 必须命中主矩阵16格（组织四层×流程四面） |
| F12/F18 | 必须为合法枚举值（7类/3类） |
| 工具编号 | 必须命中 tools.md 现有编号（或同步扩展） |
| 置信度 | 0-1 之间，标注依据 |

### 蒸馏来源

```
一手: 实际案例复盘 | 二手: 行业公开案例 | 调研: Infoseek 调研结果
每个新场景须标注来源类型（一手/二手/调研）
```

## 八、G 自进化接口（Infoseek 调研消化）

### 触发条件
```
场景库无匹配 | F10b无工序 | 工具无落格 | 字段无法表达
```

### 消化流程

```
① QCM 穿透定位缺口（四步穿透法）
② Infoseek 调研（依赖 Skillhub.cn 安装的 Infoseek Skill）
③ QCM 消化入库（按本文件 A-F 接口落地）
④ 反馈闭环（更新覆盖率统计 + 变更记录）
```

### 依赖检查

```
自进化触发时检查 Infoseek 是否安装:
  已安装 → 直接调用调研
  未安装 → 提示: https://Skillhub.cn（关键词: Info-seek）
          降级: 输出基础卡片 + [未覆盖→调研受限:缺少Infoseek]
```

## 九、H 行业蒸馏接口（新增行业适配包 · QCM 普适化总入口）

> **定位**：将 QCM 从制造业扩展到任意行业的**标准化总入口**。与 G 接口的区别：G 是单点问题自进化（一个缺口补一个），H 是整行业蒸馏（一次调研→全链路适配包）。框架蓝图见 `references/industry.md`。

### 触发条件（任一命中即启动）

```
① 端到端定位：MTL/LTC/OTC/ITR 在目标行业无对应流程
② F10b 工序细分：无目标行业工序（如 IT 的"需求评审/代码走查/部署发布"）
③ 场景库：无目标行业典型质量场景匹配
④ 用户要求行业化应用且知识库案例缺失
```

### 蒸馏流程（六步，每步有交付物）

```
阶段一 Infoseek 全景调研（信息收集）
  ① 关键词三层展开（行业×质量维度×场景）→ 多渠道嗅探
  ② Anchor_Score 锚点评分门控（≥70 核心 / 40-69 需确认 / <40 过滤）
  ③ 内容采集（URL 存活预检 → 四级降级 → 翻译摘要）
  ④ 多源交叉核验（标准+经典+交叉，产出分层根因表）
  交付物：行业调研包（价值链/标准/工具/案例/判据 五件套）

阶段二 QCM 穿透补充（结构化落位）
  ⑤ 六步导航逐层穿透：端到端→外轴→内轴→多链→横轴 16 格→纵轴→取物
  ⑥ 工具落格差异分析（复用 vs 新增）
  交付物：适配包草稿（ADAPTER 七段模板，见 industry.md 第二节）

阶段三 测试与注册（质量门控）
  ⑦ 增量测试用例补入 test-cases.md（场景→格/工具→场景双向）
  ⑧ 8 引擎全量回归（all/cross/super/reverse/loop/combo/lowfreq/full）
  ⑨ 全绿 → ima_skill_create 注册；失败 → 回阶段二修正
  交付物：🟢 已注册适配包 + 回归报告
```

### 适配包落盘位置

```
references/adapters/{行业代码}-adapter.md   （如 it-software-adapter.md）
industry.md 第四节索引表 → 登记注册
```

### 质量门控（注册前必须全过）

| 门控项 | 判据 |
|--------|------|
| 三源印证 | 每个关键判据至少 1 个权威来源（标准/经典/公开案例） |
| 双向可达 | 场景→16 格、工具→场景 无悬空 |
| 编号兼容 | 新增工具 #43 起、大师 #22 起、字段 F22 起、工序追加不重编 |
| 测试全绿 | 8 引擎 0 失败（含新增增量用例） |
| 抽象层只读 | 未改动组织四层/四面/16 格/多链/六步导航定义 |

### 与 A-G 接口的关系

```
H 触发 → 阶段一 Infoseek 调研（= G 的行业化升级版）
       → 阶段二 QCM 穿透 → 落库时按需调用：
           A 场景蒸馏（行业场景）｜ B 工具扩展（行业特有方法）
           E 流程扩展（行业工序/价值链）｜ F 知识库扩展（行业案例）
           C 大师蒸馏（行业大师，如需）｜ D 字段扩展（行业字段，如需）
```
