# 四性评估法（Four-Aspect Evaluation）

> 适用于"流程/制度/方案如何流出"的系统性评估方法。
> 通过四个维度审视任何要落地的事务（流程、规则、培训、方案、标准），回答"这套东西能不能真正跑起来"。
> 词条落盘：`keyword.yaml` 已注册 `执行有效性 / 教育符合性 / 标准适宜性 / 监督可行性`（intent ③评估审计，含英文别名）。

---

## 一、提出背景

当一项流程、制度、培训方案或标准被设计出来之后，最常被问到的问题不是"它写了什么"，而是"**它能跑得起来吗**"。传统评审只关心文档完备性，而忽略落地全链路：

```
设计 → 培训 → 执行 → 监督
```

四性评估法将这条链路拆解为四个**相互独立、可分别打分的**维度，缺一不可。

---

## 二、四个维度

### ① 执行有效性（Execution Effectiveness）
**回答**：现场人员**能不能照做**？执行后**有没有效果**？

| 检查项 | 否决性问题 |
|--------|-----------|
| 关键动作是否明确到角色 | 谁来做？ |
| 频次与节奏是否匹配实际工况 | 多久做一次？ |
| 输入条件在现实中是否齐备 | 工装/物料/系统/权限到位吗？ |
| 异常路径（断料/设备故障）有无兜底 | 出问题怎么办？ |
| 衡量指标是否可观测 | 做了怎么知道做对了？ |

**红牌情景**：写"每班巡检一次"但没指定巡检项 → 形同虚设。

### ② 教育符合性（Educational Alignment）
**回答**：相关人员**是否知道要做、为何做、怎么做**？**理解一致**吗？

| 检查项 | 否决性问题 |
|--------|-----------|
| 培训对象是否覆盖到所有执行角色 | 谁需要会？漏了谁？ |
| 培训内容是否对得上执行要点 | 教的是做的吗？ |
| 培训方式是否匹配场景复杂度 | 现场实操 vs 课堂讲解？ |
| 考核与资质是否挂钩 | 不合格能上岗吗？ |
| 新人/转岗/外协有无独立机制 | 老人带新人就够了吗？ |

**红牌情景**：培训课件停留在 2018 年版本，实际工艺 2024 年已迭代 → 知识与执行严重脱节。

### ③ 标准适宜性（Standard Suitability）
**回答**：依据的**标准/规范/制度是否适用**当前情境？条款**是否写得清楚**？

| 检查项 | 否决性问题 |
|--------|-----------|
| 标准的范围是否覆盖目标场景 | 内部标准 vs 行业/国标？ |
| 条款颗粒度是否可执行 | "适当关注" → 如何判断？ |
| 标准之间是否一致无冲突 | 与上游/下游/并行制度矛盾吗？ |
| 关键参数是否给出量化阈值 | 用数据说话还是经验判断？ |
| 版本/修订/废止机制是否清晰 | 现在用的是最新版本吗？ |

**红牌情景**：照搬"通用 SOP"套用到本厂特殊工艺 → 标准水土不服。

### ④ 监督可行性（Oversight Feasibility）
**回答**：执行过程**是否被看见**？偏差**能不能被及时发现并纠偏**？

| 检查项 | 否决性问题 |
|--------|-----------|
| 监督主体（QA/班组长/系统）是否明确 | 谁来盯？ |
| 监督频次与方式是否覆盖关键节点 | 抽查/全检/系统告警？ |
| 偏差发现→上报→处置的链路是否畅通 | 出问题多久能升级？ |
| 数据/记录是否可追溯 | 事后能复盘吗？ |
| 监督者是否具备独立性与能力 | 自己管自己？还是被考核方？ |

**红牌情景**：没有监督节点 → 出问题要等客诉才被发现。

## 三、4 维交叉判定

| 维度通过情况 | 综合判定 |
|------------|---------|
| 4 项全绿 | ✅ 可发布落地 |
| 任意 1 项黄 | ⚠️ 条件性发布，附改进清单与期限 |
| 任意 1 项红 | ❌ 暂缓发布，回炉重新设计 |
| 2 项及以上红 | ⛔ 推翻重来，重新走四性评估 |

> **原则**：单维红即一票否决。短板决定上限。

## 四、应用场景

| 场景 | 入口 | 主导维度 |
|------|------|---------|
| **新 SOP 上线** | 设计 → 评审 | ③标准适宜性 + ①执行有效性 |
| **新员工/转岗培训** | HR → 部门 | ②教育符合性 + ①执行有效性 |
| **跨部门协作流程** | 主导部门 → 协同部门 | ①执行有效性 + ④监督可行性 |
| **客诉/质量事件复盘** | 危机 → 整改 | ④监督可行性 + ②教育符合性 |
| **体系/认证审核（ISO/IATF）** | 内审 → 外审 | ③标准适宜性 + ④监督可行性 |
| **管理评审（L4 治理）** | 高管 → 体系 | 四性综合 |

## 五、与 3A5WHY 流出链的挂接（下挂点）

> **下挂语义**：3A5WHY 三链根因的**流出链**（"为什么没被拦截" → 探测根因）锁定拦截失效后，用本方法对**流出管控方案**做四性评估，验证其能否真正落地——防止"纸面拦截"。

```
3A5WHY ③ 流出链（探测根因：检具缺失/抽检不足/检验标准缺失）
   │ 5WHY 下钻 → 定位流出管控缺口
   ▼
four-aspect-evaluation（四性评估 · 下挂 M2.5 → D4 初）
   ├─ ① 执行有效性  拦截动作能否照做？（检具/抽检频次/巡检项明确到角色？）
   ├─ ② 教育符合性  检验人员会不会、知不知道拦截判据？
   ├─ ③ 标准适宜性  检验标准/抽检规范是否适用、颗粒度可执行？
   └─ ④ 监督可行性  拦截是否被看见？（QC 复核/系统防呆/异常上报链路？）
   ▼
单维红即一票否决 → 回流重设流出管控 → 再评估 → 通过后进入 3A5WHY ④纠正措施 / ⑤系统预防
```

**维度 ↔ 流出链映射**

| 四性维度 | 流出链视角的否决性问题 |
|---------|----------------------|
| ① 执行有效性 | 新检具/抽检措施现场能不能照做？谁做？多久做？ |
| ② 教育符合性 | 检验员是否经过培训、考核、上岗资质？ |
| ③ 标准适宜性 | 检验标准/抽检方案/规格界限是否适用当前产品？ |
| ④ 监督可行性 | 拦截结果是否可追溯？漏检能否被 QC/系统发现？ |

**挂接点**：`3a5why.md` ③ 根因分析 · 子级里程碑 **M2.5**（流出管控方案四性评估 → D4 初）。
