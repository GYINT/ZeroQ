# 业务报告 PDCA 机制框架方法论摘要（Reporting PDCA Framework）

> **定位**：PDCA × 5W2H × 上级报告闭环（企划-终检-实施-改善四阶段报告机制）方法论摘要。
> **完整中文操作模板**见 `references/contract/reporting-pdca-template.md`。
> **同族关系**：PDCA 改善版 / 简化问题解决流 / 8D / 危机沟通 3T。

---

## 一、核心思想

业务报告 PDCA 机制把 PDCA 循环转化为**与上级的沟通节奏**：每一阶段（P/D/C/A）都遵循"接受指示 → 5W2H 确认 → 预约上级 → 制作材料 → 报告商谈 → 按指示修改 → 再报告"的闭环，最终目标是**确保问题解决、各流程顺利实施**。

```
PDCA 循环 + 报告闭环 = 每个阶段都有"可追溯的上级确认"
  P 企划决策 → 上级批准（决策日确定）
  D 业务终检 → 上级知悉（进展/结果报告）
  C 实施结果 → 上级评价（效果确认）
  A 改善     → 上级认可（标准化手册）
```

**与普通 PDCA 的区别**：
- 普通 PDCA：关注改善动作本身
- 报告 PDCA：关注**"如何向上级报告"**——将改善过程转化为上级可见、可追溯、可纠正的沟通机制

---

## 二、四阶段报告要点

### P · 企划决策报告
- **5W2H 确认指示**（7 要素）：接受指示后第一件事
- **确定决策日期 + 预约上级**：报告节奏前置
- **报告-商谈-修改-再报告**：企划案至少 1 轮闭环

### D · 业务终检报告
- **执行 + 预约 + 报告 + 修改**：轻量闭环
- **紧急联络**：情况恶化/偏离计划时**立即**升级（不等待定期节点）

### C/A · 实施结果 + 改善报告
- **汇总实施结果 + 改善方向** → 报告书
- **商谈-修改** → **标准化（业务手册）**：沉淀为可复用资产

**与危机沟通 3T 的挂接**：
- 报告 PDCA 的"报告时限" = 3T 表的时间窗（围堵 0-30min / 消除 30min-6h / 纠正 6h-3d）
- 报告 PDCA 的"紧急联络" = 3T 的升级路径（客服→店长→总部）

---

## 四、关键判据

1. **P 阶段 5W2H 确认先行**（无确认 = 方向错误风险）
2. **每阶段均有"报告-商谈-修改"闭环**（单次报告不闭环 = 无效沟通）
3. **异常/恶化紧急联络**（≤ 24h，不等定期节点）
4. **A 阶段标准化**（业务手册更新 = 资产沉淀）
5. **全程可追溯**（预约记录/商谈纪要/修订版本）
