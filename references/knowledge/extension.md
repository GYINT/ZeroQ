# QCM extension.md · 扩展接口规范（七接口 A–G）与挂载使用指引

> **定位**：QCM 扩展接口（F 接口·外部知识蒸馏）统一规范；定义 7 类扩展接口的模板、编号与挂载流程。
> **关联**：`knowledge-base.md` §6（外部知识蒸馏入库规则）；`test-cases.md` Y-4（单测/混测/边界全绿）。
> **权威源**：本文件为 QCM 扩展机制的规范入口；版本管理见 §5，扩展编号见 §4。

---

## 1. 七接口总览（A场景 / B工具 / C大师 / D字段 / E工序 / F知识 / G自进化）

扩展机制按"作用域"拆为 7 个接口，每个接口独立编号、独立模板，互不冲突。

| 接口 | 名称 | 作用域 | 挂载位置（约定） | 编号段 |
|------|------|--------|------------------|--------|
| A | 场景 | 业务/问题场景扩展 | `references/scenarios/` | 场景# |
| B | 工具 | 质量工具/方法扩展 | `references/tools/` | 工具 #43+ |
| C | 大师 | 质量大师/人物扩展 | `references/people/`（人物库） | 大师# |
| D | 字段 | 结构字段/数据扩展 | `references/contract/`（MDS/input） | F22+ |
| E | 工序 | 工序/流程步骤扩展 | `references/protocol/` | 工序# |
| F | 知识 | 外部知识蒸馏入库 | `references/knowledge/`（本文件·外部资产层） | 书单#/案例# |
| G | 自进化 | 自我演进/反馈闭环 | runtime/auto（自动蒸馏回灌） | 迭代# |

---

## 2. 扩展接口通用模板

任一扩展接口（A–G）均遵循统一骨架，确保可被 `corpus_loader` 检索、被守卫校验：

```
- 定位（一句话：解决什么问题）
- 触发条件（何时被调用 / 由哪个意图路由进入）
- 输入/输出契约（字段、格式、边界）
- 编号规则（见 §4，唯一、与现有无重叠）
- 联动声明（与 knowledge-base / tools / masters / input-guide 的扩展字段无冲突）
- 版本（见 §5）
```

## 3. F 接口 · 外部知识蒸馏入库规则（挂载使用指引）

> 外部素材（书 / 案例 / PPT / 调研）→ 经本接口蒸馏为 QCM 知识资产，追加进 `knowledge-base.md` 对应部分，**不重构 QCM 原生结构**。

### 3.1 入库标准

```
外部素材（书/案例/PPT/调研）→ QCM 知识库入库标准:
  ① 来源标注: [类型:一手|二手|调研] [可信:A|B|C]
  ② 结构统一: 核心做法 + 代表工具/方法 + 可借鉴点 + 来源
  ③ 映射落地: 至少映射 1 个 QCM 模块（六步导航/MDS/工具/大师）
  ④ 编号兼容: 引用工具# / 人物# / 决策①-㉑ 原编号
  ⑤ 黑名单: 知乎/公众号/百度百科 不采信为权威源
  ⑥ 入库位置: knowledge-base.md 对应部分追加
```

### 3.2 应用约束（不破坏 QCM 结构）

```
✅ 允许: 知识/素材追加到 knowledge-base.md（仅扩展外部资产层）
✅ 允许: 调取时组合 QCM 模块输出
❌ 禁止: 修改 SKILL.md 核心决策/导航协议/MDS 定义
❌ 禁止: 素材内容覆盖 QCM 原生工具/大师定义
✅ 原则: 外部知识服务 QCM，不重构 QCM
```

### 3.3 挂载流程（新增外部素材 / 扩展模块）

1. **素材评估**：按 §3.1 ①–⑤ 评级（类型/可信/结构/映射/黑名单）。
2. **映射**：至少挂载 1 个 QCM 模块（六步导航 / MDS / 工具 / 大师）。
3. **编号**：沿用既有 `工具# / 人物# / 决策①-㉑`；新增扩展编号按 §4。
4. **入库**：追加到 `knowledge-base.md` 对应部分 + 更新目录（TOC）。
5. **登记**（若为独立 `.md` 文件）：
   - 登记 `references/config/corpus_manifest.yaml`（corpus 段，level=chapter / group=知识族 / freq=low）；
   - 运行 `python3 scripts/gen_corpus_index.py` 生成 `references/index/<stem>.index.yaml`；
   - 在总纲/对应章节加反向链接（`见独立知识文档 <stem>.md`），消除孤儿。
6. **验证**：
   - `python3 scripts/config_sync.py --check`（g022 不应告警未登记语料）；
   - `python3 scripts/qcm_ref_query.py --orphan`（新文件不应再出现）；
   - `python3 scripts/qcm_ref_query.py --dangling`（无新增悬空）。

### 3.4 覆盖监控

```
素材覆盖率 = 已映射素材 / 全部素材
知识引用率 = 知识库被调取次数（跟踪使用价值）
新增素材 → 按 §3 规则蒸馏 → 追加对应部分 → 更新目录
```

## 4. 扩展编号规则（唯一、与现有无重叠）

| 维度 | 既有区间 | 扩展区间 | 约束 |
|------|----------|----------|------|
| 工具 | 1–42 | #43+ | 与 1–42 无重叠（Y-4 边界 ✅） |
| 大师（人物） | 既有序列 | 顺延 | 沿用 `references/people/` 编号 |
| 决策 | ①–㉑ | ㉒+ | 与 ①–㉑ 无重叠 |
| 字段（MDS） | F1–F21 | F22+（当前已用至 F26） | 见 `input-handbook.md` §1.4 / `mds-input.md` 扩展字段 |
| 场景 / 工序 | 既有 | 顺延 | 与现有命名前缀一致（见 `naming-convention`） |

> 编号唯一规则是扩展机制的核心约束：新增扩展必须落在扩展区间内，禁止占用既有编号。

## 5. 版本管理

| 版本 | 兼容关系 | 说明 |
|------|----------|------|
| 3.0.x | 基准 | 外部知识资产统一入口（knowledge-base.md） |
| 3.x | 兼容 3.0.x | 扩展接口增量（A–G 模板成型） |
| 4.0 | 升级 | 动作阶段主·时间维度子；AO 协议 v5.0（见 `output-templates.md`） |

**升级清单**（版本跃迁时同步更新）：扩展接口模板 + 编号规则 + 入库标准 + 挂载流程。
