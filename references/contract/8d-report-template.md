## 二、阶段一 · 界定问题（D0–D2）

### 1. 事实把握（14 项必查）

| # | 项目 | 数据/确认 | 信息源 |
|---|------|-----------|--------|
| 1 | 事件名称/型号/机种 |  | 不合格通知单 |
| 2 | 发生场所/环境 |  | 现场 |
| 3 | 使用条件/关联对物件 |  | 装配图面 |
| 4 | 发生现象/问题 |  | 失效件观察 |
| 5 | 发生日期 |  | 记录 |
| 6 | 序列号/识别码/批次 |  | 批次追溯 |
| 7 | 发生数量/严重性 |  | 不合格统计 |
| 8 | 运行时长/耐久性 |  | 现场/用户数据 |
| 9 | 制造日期/库存性 |  | 出厂记录 |
| 10 | 出厂日期/库存性 |  | 出入库记录 |
| 11 | 不良规格/质量标准确认 |  | 图面/规格书 |
| 12 | 量产中不良水准确认 |  | SPC/品质月报 |
| 13 | 开发阶段良品水准比对 |  | 设计阶段数据 |
| 14 | 设计变更履历 + 其他异常履历 |  | ECO/ECN |

**关键判据**：每项必须有证据；信息源缺失项必须标注「待补」。

### 2. 真因追查

| 子步骤 | 做法 | 产出 |
|--------|------|------|
| **头脑风暴**（4M 分析：过程异常/行为/环境/发展趋势/期望值分析）| 跨职能 5-8 人 / 30-60 min | 候选原因清单 |
| **快速撇除** | 排除明显不相关因素 | 收敛候选范围 |
| **4M 分析** | 人/机/料/法/环/测六维度 | 结构化清单 |
| **5Why 分析法** | 连问 5 次"为什么" | 根因链 |
| **特性要因图（鱼骨图）** | 4M + 测 | 候选根因图 |
| **选定现状** | 与目标对比 | 差距陈述 |
| **选定目标** | SMART 化 | 目标值 + 期限 |

### 3. 对策制订

#### 3.1 临时遏制（D3 即时响应）

| 处理对象 | 动作 | 责任人 | 完成时限 |
|---------|------|--------|---------|
| 异常品处理 | 隔离 + 100% 复检 | 制造/QA | ≤ 24h |
| 不良品处理 | 退料/报废/挑选 | 仓库/QA | ≤ 24h |
| 已流出处理 | 追溯召回/客户通知 | 销售/QA | ≤ 48h |
| 库存处理 | 冻结 + 复检放行判据 | 仓库 | ≤ 24h |
| 半成品处理 | 工段间追溯隔离 | 制造 | ≤ 24h |

#### 3.2 选择重点（临时/永久对策的筛选原则）

- **品质优先**：以品质影响最大者优先
- **成本优先**：以成本/交付压力小者优先
- **中心决策法**：决策点集中，减少分支
- **重点归集法**：聚焦关键少数（柏拉图 80/20）
- **MECE 原则**：相互独立、完全穷尽

## 三、阶段二 · 要因分析（D3–D5）

### 2.1 查明要因

| 子步骤 | 做法 | 产出 |
|--------|------|------|
| 鱼骨图候选原因收集 | 4M 分析法 + 头脑风暴 | 候选因 ≥ 6 项 |
| 数据收集 | 公差/测定/N 次依赖/数据支撑 | 量化依据 |
| 暂定对策 | n=1~3 先行确认 | 小试结果 |
| 要因系统图 | 候选因 → 系统逻辑 | 系统结构 |
| 影响度试验 | 分散分析/实施计划法 | 影响排序 |
| 要因总结 | 候选因收敛 | 主要因清单 |
| 补充要因调查 | 各要因公差累加 = 总成公差 | 验证根因 |

### 2.2 验证真因（D4 关键节点）

| 验证手法 | 做法 | 通过判据 |
|---------|------|---------|
| **再现试验** | 模拟异常条件复现 | 能稳定再现 |
| **NG 再现** | 不良品条件下验证 | 现象一致 |
| **OK 再现** | 良品条件下验证 | 不发生 |
| **型式交叉** | OK 件与 NG 件对比 | 关键因子明确 |

**关键自问（验证闭环）**：
- **系统为什么会再现？** → 找体系/流程漏洞
- **流出的原因？** → 拦截/探测失效
- **系统为什么会流出去？** → 探测机制/监督失效

> **与 3A5WHY 流出链的挂接**：若"流出的原因"指向探测失效/拦截失效，下挂 `methods/four-aspect-evaluation.md` 对新设计的流出管控方案做四性评估（执行有效性/教育符合性/标准适宜性/监督可行性）。

## 四、阶段三 · 确定方案（D5–D7）

### 3.1 长期消除（D5–D6）

| 子步骤 | 做法 | 产出 |
|--------|------|------|
| **预防再现**（永久对策设计）| 针对根因设计消除方案 | 对策方案 ≥ 1 项 |
| **再发原因** | 消除技术根因 | 技术方案 |
| **控制方法面** | PFMEA/控制计划/作业指导书更新 | 文件变更 |
| **系统管理面** | 管理体系缺口审视 | 管理方案 |
| **内部巩固** | 标准化 + 改善 | 文件归档 |
| **改善** | 写入标准作业 + 横向展开 | 经验沉淀 |
| **细化必要** | 多方商谈 → 锁定细节 | 共识纪要 |
| **临时措施** | 中长期临时缓解 | 过渡方案 |
| **发生原因** | 技术根因消除 | D5 输出 |
| **再发原因** | 系统根因消除 | D6 输出 |
| **控制方法** | PFMEA + CP 更新 | D7 输出 |

**判据**：临时措施 24h 落地；永久措施经中量试作验证（≥ 100 件）；发生面+流出面均有对应。
