# RACI 角色责任矩阵模板（RACI Responsibility Matrix Template）

> **定位**：基于 RACI（**R**esponsible 执行 · **A**ccountable 责任 · **C**onsulted 咨询 · **I**nformed 知情）四角色的中文可填写矩阵，扩展为 4 层级 × 5 列 20 格的完整责任分配。
> **与 QCM 既有资产的关系**：责任层协议见 `references/protocol/action-orders.md §5 责任层定义`（动作阶段+责任主体双轴）；PDCA Plan 阶段 Who 维度见 `methods/pdca-qc-framework.md`；危机管理责任升级见 `action-orders §3.3 3T × 3 列表`。
> **触发词**：RACI / 角色责任矩阵（已落盘 `keyword.yaml`，intent ②流程优化）。
> **与 5W1H/5W2H 同族**：RACI 是 Who 维度的具体化工具，与 5W1H/5W2H 配合使用。

## 二、4 层级定义

| 层级 | 角色定位 | 责任特征 |
|------|---------|---------|
| **决策或设定目标（Decision）** | 战略层 / 高管 / 治理层 | 定方向、批方案、授权资源 |
| **执行管理（Management）** | 战术层 / 中层经理 / 部门负责人 | 把决策落地、监控进展、闭环改进 |
| **专业与支持（Support）** | 专家层 / 顾问 / 职能部 | 提供专业判断、协调资源、给出建议 |
| **具体或基层工作（Execute）** | 操作层 / 一线员工 / 班组长 | 执行动作、收集数据、提交产出 |

## 四、记录模板（最小可用）

```markdown
## RACI 矩阵 · [项目/流程/议题]

- 项目/流程：
- 责任人（A 总负责）：
- 时间窗：
- RACI 原则：每行只能有 **1 个 A**；R 可以多人；C/I 可多个；模板用 R/A/C/I 或 —（无）标注

| # | 活动/任务 | 决策 | 管理 | 支持 | 执行 |
|---|----------|------|------|------|------|
| 1 | [任务 1] | A | R | C | I |
| 2 | [任务 2] | I | A | C | R |
| 3 | [任务 3] | — | R | A | C |
| ... |

### 角色名单（按层级）
- **决策层（Decision）**：[姓名/角色 1]、[姓名/角色 2]
- **管理层（Management）**：[姓名/角色 3]、[姓名/角色 4]
- **支持层（Support）**：[姓名/角色 5]
- **执行层（Execute）**：[姓名/角色 6]、[姓名/角色 7]

### 校验
- □ 每行只有 1 个 A
- □ 没有空白格子（用 — 标识）
- □ C/I 与 R 的沟通路径有 SOP
- □ 跨层级升级路径已定义（如 R 不可达时升级到 A）
```

## 五、检查清单

```
□ 4 层级（决策/管理/支持/执行）角色已识别
□ 每个任务都标注 R/A/C/I（每行仅 1 个 A）
□ A 总负责人已签字承诺
□ C（咨询）双方已就咨询时机/方式达成一致（事前/事中）
□ I（知情）双方已就通报方式达成一致（书面/会议）
□ 跨层级升级路径已明确（Escalation Path）
□ 与 PDCA 5W1H 的 Who 维度对齐
□ 与 action-orders §5 责任层定义对应
```

## 七、最佳实践

1. **每行 A 唯一**——多人 A = 无人 A
2. **A ≠ R** 时风险上升（A 是终责，R 是执行，分离会让执行者无责）
3. **C 应在决策早期介入**——事后咨询已无影响
4. **I 不要泛滥**——太多 I 会制造"信息过载"，关键节点才 I
5. **跨层级协作**用"标准化"列，避免职责真空
6. **RACI 不是一次性的**——议题/项目变化时同步更新
