# 问题解决流操作模板（Problem Solving Flow）

> **定位**：基于**简化 4 阶段问题解决流**（界定问题 → 要因分析 → 确认方案 → 落地执行）的**中文可填写操作模板**。
> **与 QCM 既有同族方法的关系**：
> - **8D 完整版**（5 阶段 D1–D+ · 14 项事实把握）→ 见 `references/contract/8d-report-template.md`
> - **PDCA + 5W1H + QC/CDA**（4 阶段 + 计划工具）→ 见 `references/contract/pdca-qc-template.md`
> - **3A5WHY 根因细化**（三链根因）→ 见 `references/methods/3a5why.md`
> - **本模板** = 8D 的**简化版**（适用不需要完整 8D 流程的轻量场景）

---

## 一、4 阶段总览

```
界定问题 ─→ 要因分析 ─→ 确认方案 ─→ 落地执行
   │           │            │            │
   │           │            │            └─ 过程反馈
   │           │            │            └─ 总结提升（合并到此阶段）
   │           │            └─ 融入创新
   │           └─ 选择重点
   └─ 确定目标
```

| 阶段 | 核心目标 | 关键交付物 |
|------|---------|----------|
| **界定问题** | 摸清事实 · 锚定范围 | 异常描述 + 现状数据 + 目标值 |
| **要因分析** | 找到真因 | 候选因清单 + 结构化根因 + 重点因 |
| **确认方案** | 选定对策 · 验证有效 | 备选清单 + 步骤细化 + 有效性确认 |
| **落地执行** | 实施 · 控制 · 反馈 | 计划 + 风险预案 + 过程反馈 + 总结提升 |

---

## 二、阶段一 · 界定问题

| 子步骤 | 做法 | 输出 |
|--------|------|------|
| **发现异常** | 数据/现场/客户反馈识别偏差 | 异常报告 |
| **优选顺序** | 多个异常时按影响×紧迫度排序 | 优先级列表 |
| **描述现状** | 5W2H / 5W1H 陈述 | 问题陈述 |
| **确定目标** | SMART 化（具体/可衡量/可达成/相关/时限）| 目标值 + 期限 |

**关键判据**：目标可量化；现状可对比；范围有边界（不扩大化）。

---

## 三、阶段二 · 要因分析

| 子步骤 | 做法 | 输出 |
|--------|------|------|
| **列挙要素** | 头脑风暴（4M/6M）· 候选因全清单 | 候选因 ≥ 6 项 |
| **结构细化** | 鱼骨图 4M + 测层级 | 结构化根因图 |
| **内部归因** | 区分内部/外部；锁定可控范围 | 内因清单 |
| **选择重点** | 柏拉图 80/20 / 数据支撑 · 选关键少数 | 主要因清单 |

**关键判据**：要因有数据支撑；区分可控 vs 不可控；候选因收敛到 1-3 项重点。

---

## 四、阶段三 · 确认方案

| 子步骤 | 做法 | 输出 |
|--------|------|------|
| **建立备选** | 针对重点要因设计 ≥ 2 个对策 | 对策清单 |
| **细化步骤** | 5W1H（What/Why/How/When/Who/Where）+ RACI | 实施 SOP |
| **融入创新** | 借鉴他山 / 跨域类比 / 标杆对照 | 创新点 |
| **有效确认** | 小范围试作 + 效果数据验证 | 中量试作报告 |

**关键判据**：备选有 ≥ 2 个；试作验证有效；中量试作 ≥ 100 件。

---

## 五、阶段四 · 落地执行（含总结提升）

| 子步骤 | 做法 | 输出 |
|--------|------|------|
| **制定计划** | 全员宣导 + 责任分配（RACI）+ 时间表 | 实施计划 |
| **风险预控** | 识别实施风险 + 兜底方案 + 升级路径 | 风险预案 |
| **过程反馈** | 推移图追踪 + 异常上报 + 即时纠偏 | 推移图 + 周报 |
| **总结提升** | 标准化 + 成果报告 + 横向推广 | 标准化文件 + 报告书 |

**关键判据**：风险有预案；过程可追溯；总结可推广（防局部最佳实践）。

---

## 六、检查清单（最小可用交付物）

```
□ 界定：现状描述含 5W2H · 目标 SMART 化
□ 界定：异常边界明确
□ 要因：候选因 ≥ 6 项 + 鱼骨图 4M 展开
□ 要因：主要因有数据支撑 · 区分内外/可控
□ 方案：备选 ≥ 2 个 + 5W1H 细化 + RACI 分配
□ 方案：中量试作验证 ≥ 100 件 · 有效确认
□ 执行：风险预案 + 升级路径
□ 执行：推移图追踪 ≥ 4 周数据点
□ 执行：标准化文件 + 成果报告书 + 横向推广
□ 与既有体系挂接：8D 报告（重大异常升级）/ 3A5WHY（根因细化）/ 四性评估（落地执行末尾）
```

## 七、与 QCM 既有方法的同族关系

```
简化问题解决流（本模板 · 4 阶段）
  ├─ 8D（Ford 5 阶段 · 完整版 · 客户投诉/重大异常）→ contract/8d-report-template.md
  ├─ PDCA + 5W1H + QC/CDA（戴明环 · 改善活动）→ contract/pdca-qc-template.md
  ├─ 3A5WHY（三链根因 · 发生/流出/系统）→ methods/3a5why.md
  ├─ 四性评估（落地执行末尾 · 流出管控方案验证）→ methods/four-aspect-evaluation.md
  └─ RACI（阶段三 Who 维度 + 阶段四 责任分配）→ contract/raci-matrix-template.md
```

**选择指南**：
| 场景 | 首选 |
|------|------|
| 客户投诉 / 重大异常 / 逃逸缺陷 | **8D 完整版** |
| 品管圈 / 一般改善活动 | **PDCA + 5W1H** |
| 现场快速问题（无需完整流程）| **本简化版** |
| 根因深挖 / 三链分析 | **3A5WHY** |
| 责任不清 / 跨职能协作 | + **RACI** |
| 落地执行末尾 · 防"纸面流出" | + **四性评估** |
